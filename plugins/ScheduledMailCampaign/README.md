# 批量定时邮件

此插件用于批量、可控地发送站内邮件。它只负责将邮件任务投入 `send_email` 队列，实际 SMTP 发送与失败重试由项目的 `SendEmailJob` 完成。

## 与旧版 CronMailSender 的区别

- 不在调度任务内同步发送 SMTP，也不会 `sleep()` 阻塞调度器。
- 每分钟仅投递一批队列任务，可设置每封邮件的队列延迟。
- 通过活动批次编号独立保存进度；递增编号即可立即开始新的完整活动。
- 邮件正文按纯文本转义，避免内容中的 HTML 被执行。
- 支持仅发送有效用户以及按用户 ID / 邮箱排除账户。

## 使用方式

1. 确保队列 Worker 或 Horizon 正常运行，并消费 `send_email` 队列。
2. 安装并启用插件，设置标题、正文和活动批次编号。
3. 设置每分钟投递数量与单封间隔，避免超过 SMTP 服务商限额。
4. 开启插件。插件会从用户 ID 最小的符合条件账户开始，分批续跑。

## 活动批次与周期

- 同一个**活动批次编号**完成所有符合条件用户后，插件记录完成时间，并按“完整发送间隔”等待下一轮。
- 修改标题、正文或收件规则后，如需立即重新发送给全部目标用户，请将活动批次编号加 1。
- 未完成的批次使用缓存游标续跑。若清除项目缓存，当前批次会从头开始，可能产生重复投递；大规模活动前请避免清缓存。

## 收件范围

- 默认发送给所有有非空邮箱的用户。
- “仅发送给有效用户”启用后，要求用户未封禁、可用流量大于 0，且套餐未到期或为长期有效。
- 排除用户 ID / 排除邮箱为或关系，任一命中都会跳过。

## 邮件发送结果

每封邮件由 `SendEmailJob` 最多重试 3 次，最终发送记录及错误信息保存在系统邮件日志中。队列未运行时，邮件不会丢失，但会停留在队列中等待处理。
