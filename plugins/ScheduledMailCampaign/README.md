# 批量定时邮件

此插件用于批量、可控地发送站内邮件。每次任务会在插件内逐封调用 SMTP，并在两封邮件之间按配置 `sleep`，不依赖队列延迟。

## 与旧版 CronMailSender 的区别

- 每次只处理配置数量的用户，并在同一批中逐封发送。
- 每封发送完成后按配置 `sleep`；间隔为 3 秒时，下一封不会早于上一封完成后的 3 秒发送。
- 批次运行期间同时持有调度器锁与动态时长缓存锁；当前整批未结束前，下一分钟的调度不会启动第二个批次。
- 通过活动批次编号独立保存进度；递增编号即可立即开始新的完整活动。
- 邮件正文按纯文本转义，避免内容中的 HTML 被执行。
- 支持仅发送有效用户以及按用户 ID / 邮箱排除账户。

## 使用方式

1. 确保 Xboard 的计划任务正常运行。
2. 安装并启用插件，设置标题、正文和活动批次编号。
3. 设置“每次批量处理数量”和“单封发送间隔”。例如数量为 `20`、间隔为 `3` 秒时，一批最多持续约 57 秒加 SMTP 发送耗时。
4. 开启插件。插件会从用户 ID 最小的符合条件账户开始，分批续跑。

推荐从“每批 20 封、间隔 3 秒”开始。批量数量最多 100 封，发送间隔最低 1 秒；小于范围的配置会自动按边界值执行。

计划任务必须每分钟运行一次，例如：

```bash
* * * * * cd /你的/Xboard/目录 && php artisan schedule:run >> /dev/null 2>&1
```

插件不依赖 Horizon 或 `send_email` 队列；邮件就在计划任务进程中逐封发送。

## 活动批次与周期

- 同一个**活动批次编号**完成所有符合条件用户后，插件记录完成时间，并按“完整发送间隔”等待下一轮。
- 修改标题、正文或收件规则后，如需立即重新发送给全部目标用户，请将活动批次编号加 1。
- 未完成的批次使用缓存游标续跑。若清除项目缓存，当前批次会从头开始，可能产生重复投递；大规模活动前请避免清缓存。
- 关闭“启用插件”会阻止下一批开始，但不能中断当前正在同步发送的批次，也不能撤回已发出的邮件。
- 如果服务器强制终止了正在发送的批次，确认没有任务在运行后可执行 `php artisan schedule:clear-cache` 清理残留的调度器锁。

## 收件范围

- 默认发送给所有有非空邮箱的用户。
- “仅发送给有效用户”启用后，要求用户未封禁、可用流量大于 0，且套餐未到期或为长期有效。
- 排除用户 ID / 排除邮箱为或关系，任一命中都会跳过。

## 邮件发送结果

每封邮件会直接记录在系统邮件日志中；发送失败将记录错误，但不会阻断本批其余邮件。由于发送在计划任务进程中同步执行，批量数量和间隔不宜设置过大。
