# 自动工单回复

插件每分钟检查待处理工单，并按关键词规则自动回复。回复数据会先在事务内保存；事务提交成功后，邮件才会加入发送队列。

## 配置说明

- **管理员用户 ID**：必须填写已存在且 `is_admin=1` 的账户，否则插件会跳过本轮处理并记录错误。
- **每轮最多处理工单数**：默认 50，范围 1 至 200。
- **仅关键词命中时回复**：建议对提现、投诉等需要人工判断的站点开启。开启后，未命中规则的工单不会自动回复。
- **默认回复内容**：仅在关闭“仅关键词命中时回复”时使用；留空也不会自动回复。
- **关键词规则**：一行一条，格式为 `关键词1|关键词2=>回复内容`。优先匹配靠前的规则。
- **排除用户 ID / 排除邮箱**：匹配的账户不会自动回复；支持换行、逗号、分号分隔。
- **邮件模板名**：默认 `cronnotify`，应与当前主题下的邮件模板保持一致。

## 处理与通知

1. 插件对单张工单加行级锁，避免多个调度进程重复回复。
2. 只会回复最后一条消息仍由工单用户发送的待处理工单。
3. 工单回复成功提交后，触发 `ticket.reply.admin.after` Hook，并通过 `send_email` 队列发送邮件。
4. 邮件任务最多重试 3 次；最终状态可在邮件日志中查看。邮件失败不会回滚已提交的工单回复。

请确保队列 Worker/Horizon 正常运行，否则邮件只会停留在队列中，工单内的自动回复仍会正常生成。
